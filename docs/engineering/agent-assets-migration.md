# Agent 工作资产借鉴与迁移说明

本次审阅对象是 `/Users/cfd/workstation/Agents/deepseek-harness/.agents`。盘点结果约有 2,083 份历史 Note 和 11 个技能目录。最终只移植通用维护方法，并以 OpenSpec 作为 DSH Forge 的提案和决策来源。

## 值得借鉴的内容

### 1. 让 prose 保留契约而不是过程

上游的 prose 标准和推理残留清理规则很适合新项目：文档和注释应说明责任、前置条件、后置条件、失败行为、所有权和安全边界；不应记录“先做了什么、评审说了什么、旧版本怎样”。这些规则被合并到 `.agents/skills/dsh-forge-prose-standard`。

### 2. 把审查和验证按风险分层

代码审查优先检查正确性、生命周期、安全性和公开契约；提交前只运行能覆盖当前变更的最小证据，避免把“全量运行”当成质量本身。对应技能分别位于 `.agents/skills/dsh-forge-code-review` 和 `.agents/skills/dsh-forge-pre-push-checks`。

### 3. 用证据驱动简化

删除或合并能力前先搜索生产调用方、动态加载路径、配置和文档引用，区分真正的死代码与有意保留的扩展点。对应规则位于 `.agents/skills/dsh-forge-simplification`。

## 不直接移植的内容

- 上游运行时实现 Note：涉及 agent loop、Cordis、ACP、会话事件和内部包拓扑，不能约束 DSH Forge 的发行版组合。
- Agent Note 生命周期和归档技能：当前项目不采用该目录体系，提案和历史变更统一由 OpenSpec 管理。
- 双语翻译技能和配对清单：当前项目明确采用中文单语设计文档，英文版本出现后再单独设计配对门禁。
- 文档站点同步技能：当前没有 `website/`、VitePress 或生成投影目录。
- 浏览器 GIF、桌面 UI 证据链：当前项目还没有可运行的桌面产品入口，不能制造虚假的演示门禁。
- 堆叠 PR、上游发布和 CI 专用脚本：这些依赖远程仓库策略和现有工作流，等基础设施落地后再移植。

## 启用条件

- 出现第二种文档语言：新增翻译规则、术语表和配对一致性记录。
- 建立 VitePress 或其他站点：新增明确的 Markdown 清单、投影目录和站点检查。
- 桌面应用进入可运行状态：再启用真实服务器、真实模型流和隔离状态的 UI 录屏证据链。
- CI 与发布流程稳定：把提交前技能中的手工检查替换为仓库脚本，并在 OpenSpec 变更中记录门禁所有权。
