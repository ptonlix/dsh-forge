# DSH Forge 简化审计

这是证据驱动的审计，不是“看起来复杂就删”。优先提出少量能够减少真实维护成本的候选。

## 强候选

- 公开方法、事件、配置项、注册通知或包没有生产消费者。
- 两个持久化或运行时表示重复保存同一个事实。
- 每个实现都必须提供但没有调用方使用的扩展点。
- 只为演示或测试而存在的独立包增加了发布和依赖成本。
- 没有产品所有者的投机通用能力增加了 API、状态或回滚路径。
- 手写协议解析、重试、glob 或 diff 逻辑可由可靠的 Node 内置或健康依赖完整替代，且替换后净删除量为正。

## 证据流程

1. 用 `rg` 搜索符号、事件、配置键、包名和动态字符串。
2. 区分生产代码、构建脚本、示例、测试、文档和 OpenSpec 变更的消费者。
3. 阅读调用点，确认没有动态加载、配置生成、插件注册或外部入口。
4. 检查现有设计文档和 OpenSpec 变更是否已经明确保护该扩展点。
5. 计算净删除：实现、测试、文档和维护路径减少的部分，减去新增适配层。

## 不能直接删的情况

生产调用方存在、公开兼容性仍需支持、持久化或 wire 格式仍在使用、或决策理由尚未被新证据推翻时，降级为提案或拒绝。不要仅凭 `knip`、测试数量或“未来可能用到”做结论。

真正的行为删除必须先创建 OpenSpec 变更，列出问题、替代方案、风险、放弃的能力、重新引入条件和可验证的任务；完成后归档该变更。
