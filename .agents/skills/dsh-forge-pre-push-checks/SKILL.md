# DSH Forge 提交前检查

本技能只选择证据，不代替提交授权。先看变更，再选择能捕获该变更回归的最小检查；没有检查脚本时，诚实报告当前只能完成的验证。

## 变更范围

```sh
git status --short --branch
git rev-parse --show-toplevel
git diff --stat
```

不要猜测 PR 基线、远程分支或未提供的环境状态。存在未跟踪文件时，把它们纳入范围判断。

## 证据选择

- 文档、OpenSpec 变更或文档链接：运行 `git diff --check`，并搜索旧路径、断链和重复名称。
- profile、bundle、插件清单或构建配置：运行对应解析、构建和启动 smoke；若尚未实现脚本，标记为未覆盖。
- IPC、子进程、文件系统或网络行为：运行拥有该边界的聚焦测试，并覆盖失败和释放路径。
- 公共 API、包导出或持久化格式：运行类型检查、构建和兼容性测试；不要只运行单元测试就声称完整。

测试选择和覆盖选择分开；不要用“允许无测试”、降低阈值或过窄的范围掩盖未覆盖代码。

## 失败处理

相关检查失败时，停止声称变更可交付，修复或说明阻塞原因。环境限制必须记录确切命令和失败位置；不得用未授权的绕过方式替代必需检查。

## 推送纪律

普通推送前检查工作树和实际验证结果。历史重写只使用 `--force-with-lease`，禁止裸 `--force`。本技能不执行 `git commit`、`git push` 或删除操作，除非用户另外明确授权。
