## Purpose

为 DSH Forge 建立可追溯的公开文档边界和中英文一致性契约，使所有公开文档能够在 GitHub、文档站和维护流程中保持同一套当前事实。

## ADDED Requirements

### Requirement: 公开文档必须具有唯一归属和明确范围
仓库 SHALL 将面向发行版用户、Fork 维护者、公开 service consumer 和本项目贡献者的文档纳入公开文档范围；每个纳入范围的事实 MUST 只有一个 canonical Markdown 所有者。`AGENTS.md`、`openspec/**`、双语治理规则自身以及未被公开发布清单选择的内部记录 MUST 不因本变更自动进入公开双语范围。

#### Scenario: 新增公开文档
- **WHEN** 维护者新增面向用户、Fork、公开 service 或贡献者的 Markdown 文档
- **THEN** 文档必须放入已声明的所有权目录，并同时创建英文源、中文对侧和一致性记录

#### Scenario: 发现无关文档
- **WHEN** 文档审查发现某文件不描述 DSH Forge 的发行版、工具链、桌面宿主、公开 service 或维护流程
- **THEN** 该文件必须从公开文档清单移除或删除，并且仓库内不得保留指向它的当前文档链接

### Requirement: 纳入范围的文档必须以三文件形式配对
每个公开文档 SHALL 由同目录的英文 `foo.md`、中文 `foo.zh.md` 和 `foo.i18n.yaml` 组成。两种语言对公开行为具有同等权威；任一侧变更后，配对记录 MUST 在确认对侧同步后更新。配对记录 MUST 保存两侧当前确认内容的 Git blob hash。清单中的 `internalBilingual` 文档 SHALL 使用相同的三文件配对和校验规则，但 MUST 同时位于 `excluded`，不得进入公开站点。

#### Scenario: 完整配对通过检查
- **WHEN** 英文、中文和一致性记录均存在，且两侧 blob hash 与记录一致
- **THEN** 双语配对检查通过并报告该配对为一致

#### Scenario: 缺少对侧或记录
- **WHEN** 公开范围内只有英文、中文或一致性记录中的部分文件
- **THEN** 双语配对检查失败，并指出缺失文件，不允许 `docs:check` 通过

#### Scenario: 内容发生漂移
- **WHEN** 任一侧内容改变但一致性记录仍指向旧 blob hash
- **THEN** 检查失败并要求先更新另一侧，再显式重写该配对记录

### Requirement: 双语文档必须保留可验证的结构和链接语义
公开配对的两侧 SHALL 保留相同的标题层级顺序、列表形状、表格行列结构、代码围栏序列和相对文档链接语义。中文侧 MUST 提供返回英文侧的切换链接，英文侧 MUST 提供返回中文侧的切换链接；属于双语范围的相对链接必须分别指向对应语言的兄弟文件。

#### Scenario: 结构或链接不一致
- **WHEN** 两侧的标题层级、代码围栏、列表/表格形状或双语相对链接无法一一对应
- **THEN** 配对检查失败并指出结构或链接差异

#### Scenario: 语言切换链接存在
- **WHEN** 读者打开公开文档的任一语言版本
- **THEN** 文档头部提供可解析的另一语言链接，且链接不指向不存在的文件

### Requirement: 公开文档门禁必须覆盖现有文档契约
`docs:check` SHALL 同时检查公开范围发现、Markdown 尾随空格、相对链接、文档命令、标记配置示例、公开 service README 边界和双语配对。`check:all` SHALL 包含该检查；门禁不得把未执行的站点部署、签名或平台 smoke 报告为已通过。

#### Scenario: 文档引用不存在命令
- **WHEN** 文档中的 `pnpm run <command>` 未在根 `package.json` 声明
- **THEN** `docs:check` 失败并指出文件和命令

#### Scenario: 全量检查通过
- **WHEN** 公开文档、包 README、双语配对和现有契约检查全部满足
- **THEN** `docs:check` 与 `check:all` 返回成功，并报告实际检查文件数量

### Requirement: 文档清理必须先处理入站引用
删除或移出公开范围的文档 MUST 在变更中记录原因、替代权威来源和入站链接检查结果；删除后，README、设计文档、包 README、脚本和网站发布清单不得继续引用该路径。删除操作不得修改用户未授权的目录或构建产物。

#### Scenario: 删除无引用文档
- **WHEN** 文档已确认无当前入站引用且不属于公开事实
- **THEN** 允许删除或移出公开范围，并在任务验证中保留路径检查证据

#### Scenario: 文档仍有入站引用
- **WHEN** 待删除文档仍被当前文档、脚本或发布清单引用
- **THEN** 必须先迁移引用到权威替代文档或明确修正文档，再允许删除
