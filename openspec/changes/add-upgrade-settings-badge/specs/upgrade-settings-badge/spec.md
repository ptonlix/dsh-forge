## Purpose

让用户在不打开设置面板的情况下即可知道有可用版本，并通过既有的升级管理页面完成受控升级。

## ADDED Requirements

### Requirement: 设置入口必须显示被动升级提示

支持 OTA 的桌面发行包在主进程升级状态为 `available` 时，设置入口 MUST 显示“发现新版本”的可见提示。提示 MUST 是非阻塞的，不得自动打开设置、弹出对话框、下载完整安装包或改变当前 generation。

当状态为 `idle`、`checking`、`current`、`preparing`、`error` 或 `unsupported`，或 Remote 不可用时，设置入口 MUST NOT 显示“发现新版本”提示。

#### Scenario: 自动检查发现新版本

- **WHEN** generation 完成静默检查并返回可用版本
- **THEN** 设置入口显示橙色提示，且当前页面和会话不被打断

#### Scenario: 没有可用版本

- **WHEN** 主进程返回当前版本、检查失败或平台不支持 OTA
- **THEN** 设置入口不显示新版本提示

### Requirement: 升级管理导航项必须同步显示提示

当设置面板打开且升级状态为 `available` 时，设置导航中的“升级管理”项 MUST 显示同一枚
橙色提示点或等价的可见提示，并标注“发现新版本”，使用户能够定位到具体功能。

当设置面板关闭、升级状态不再为 `available`、Remote 不可用或导航项尚未挂载时，导航项
提示 MUST 隐藏或不创建；导航项本身的点击行为 MUST 保持不变。

#### Scenario: 打开设置后定位升级管理

- **WHEN** 设置入口已有可用版本提示，用户打开设置面板
- **THEN** “升级管理”导航项显示橙色提示，点击该项仍只切换到升级管理页面

#### Scenario: 可用版本失效

- **WHEN** 后续状态变为当前版本、检查失败或不支持 OTA
- **THEN** 已挂载的“升级管理”导航项提示被移除，导航项仍可正常使用

### Requirement: 升级管理导航项必须使用独立图标

“升级管理”导航项 MUST 使用区别于通用设置齿轮的更新语义图标；图标颜色 MUST 跟随导航项
现有的默认、悬停和选中状态，图标替换不得改变导航项的点击、焦点或无障碍行为。

#### Scenario: 显示升级管理导航项

- **WHEN** 设置面板显示“升级管理”导航项
- **THEN** 导航项显示更新/刷新语义图标，而不是通用设置齿轮

### Requirement: 提示必须遵守既有升级确认流程

用户点击带有升级提示的设置入口后，系统 MUST 保持既有设置打开行为，并通过“升级管理”页面提供“立即升级”操作。升级操作 MUST 继续调用无参数 `upgradeManager/startUpgrade`，由主进程重新检查并显示原生确认；用户确认前不得下载完整安装包。

renderer MUST NOT 接收或传递更新 URL、暂存路径、命令、版本候选或 Electron 对象。

#### Scenario: 用户从提示进入升级

- **WHEN** 用户点击带有“发现新版本”提示的设置入口并在升级管理页点击“立即升级”
- **THEN** 主进程重新检查可用版本，确认通过后才下载并交给既有平台安装器

#### Scenario: 用户拒绝升级

- **WHEN** 用户在原生确认中拒绝或关闭升级
- **THEN** 当前应用继续运行，且 renderer 不执行下载或安装命令

### Requirement: 提示组件必须结束自身异步工作

设置入口在挂载时 MUST 读取当前升级状态，并可按受控间隔刷新状态；组件卸载或 generation 释放后 MUST 停止刷新，不得写回已失效的组件状态。

#### Scenario: 设置入口卸载

- **WHEN** renderer 卸载设置入口或切换到新的 generation
- **THEN** 轮询 timer 被清理，迟到的 Remote 结果不会触发状态更新或异常
